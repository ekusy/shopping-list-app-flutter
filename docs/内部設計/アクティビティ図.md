# アクティビティ図

このドキュメントは、[ユースケース.md](./ユースケース.md) の各 UC について「処理の流れ」と
「分岐（どんな条件で何が起きるか）」をアクティビティ図（mermaid `flowchart`）で示す。
1 UC = 1 図を原則とする。

> **本書の方針**: 図中には**具体的な関数名・クラス名・API 名を極力書かず**、処理の意味と分岐の
> 説明に集中する。実装エントリ（画面 / コントローラ / リポジトリのクラス・メソッド）は
> [ユースケース.md](./ユースケース.md) の各 UC 表、エラーコード（`AppErrorCode`）の正本は
> [エラー仕様.md](../外部仕様/エラー仕様.md) を参照。動的なデータの流れは
> [データフロー.md](./データフロー.md)、状態の遷移は [状態遷移.md](./状態遷移.md) を参照。

## 凡例

```mermaid
flowchart TD
    S([開始 / 終了]) --> A[処理ステップ]
    A --> Q{分岐条件}
    Q -->|条件成立| B[処理]
    Q -->|失敗| ERR([エラー表示して中断]):::err
    B --> E([終了])
    classDef err stroke-dasharray: 4 3
```

- **角丸（stadium）** = 開始 / 終了。
- **長方形** = 処理ステップ（何をするか）。
- **ひし形** = 分岐（バリデーション / ガード条件）。
- **破線枠の終了** = 失敗してエラー表示で終わる経路（UI はトースト or インライン表示）。
- 一覧の更新が必要な書き込み系 UC は、**保存後にリアルタイム同期で一覧へ自動反映**される
  （画面側で明示的に再描画しない）。図では「自動反映」と注記する。詳細は
  [データフロー (a)](./データフロー.md#a-snapshots-双方向購読)。

## 7. よく買う物（#43）

### UC-F1 テンプレート一覧・追加

直接追加はアイテム追加（UC-I1）と同じ 2 段保存で画像に対応する。

```mermaid
flowchart TD
    S([開始]) --> IN[テンプレート名・タグ・メモ・写真を入力]
    IN --> Q1{プランの上限に達している?\n無料 10 / 有料 無制限}
    Q1 -->|超過| E1([エラー: よく買う物の上限\nfavorites.error.limit_exceeded]):::err
    Q1 -->|可| W[ステップ1: addFavorite\nimageUrl 空・既存最大 order + 1 を付与]
    W --> Q2{ドキュメント作成成功?}
    Q2 -->|失敗| E2([エラー表示]):::err
    Q2 -->|成功| Q3{新規画像あり?}
    Q3 -->|なし| OK[一覧へ自動反映（watchFavorites ストリーム）]
    Q3 -->|あり| UP[ステップ2: uploadFavoriteImage →\nupdateFavorite で imageUrl 更新\n（best-effort: 失敗してもテンプレート本体は残す）]
    UP --> OK
    OK --> E([終了])
    classDef err stroke-dasharray: 4 3
```

> **編集時**: 新規画像があれば `uploadFavoriteImage` → `updateFavorite` で URL 更新。画像を外した場合は更新後に `deleteFavoriteImage` を best-effort 実行。**削除時**: ドキュメント削除後に `deleteFavoriteImage` を best-effort 実行して孤児画像を防ぐ（favorites には Functions トリガが無いため）。画像パスは `groups/{groupId}/favoriteItems/{favoriteId}.jpg` で、グループ削除時は `onGroupDeleted` の `groups/{gid}/` prefix 一括削除で清掃される。
